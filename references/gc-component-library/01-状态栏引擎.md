🌟 状态栏书写完全指南（超详细版）

一、状态栏是什么

状态栏是显示在AI回复下方的信息卡片。AI在正文末尾输出特定格式的数据，平台通过正则将数据转换为可视化面板，显示角色的各项数值、进度条、选项按钮等。

工作流程：

```
AI输出文本 → 正则1 → 隐藏数据 → 正则2 → 插入组件 → 引擎读取 → 渲染卡片
```

---

二、三段正则结构

状态栏部署需要三条正则表达式，按以下优先级排列：

正则 查找内容 替换为 位置
正则1（数据隐藏层） `/\[#([^=\[\]#]+)=([^\[\]#]+)#\](?:\s <br\s/?>)/gi` <span class="z-live-data" style="display:none">[#$1=$2#]</span>
正则2（UI触发层） <GC_UI> 一段HTML（见下方） 聊天区
正则3（引擎层） <GC_SCRIPT> 完整引擎代码 功能栏

---

正则1详解

查找内容：

```
/\[#([^=\[\]#]+)=([^\[\]#]+)#\](?:\s|<br\s*\/?>)*/gi
```

这串天书拆开看：

· \[# 匹配 [# 开头
· ([^=\[\]#]+) 捕获键名，排除 =、[、]、# 四个字符
· = 匹配等号
· ([^\[\]#]+) 捕获键值，排除 [、]、# 三个字符
· #\] 匹配 #] 结尾
· (?:\s|<br\s*\/?>)* 吞掉行尾的换行或 <br> 标签
· gi 全局匹配 + 忽略大小写

替换内容：

```html
<span class="z-live-data" style="display:none">[#$1=$2#]</span>
```

$1 是键名，$2 是键值。这行把AI输出的 [#生命值=85#] 变成隐藏的 <span>，引擎从这些span里读数据。

四、关键提醒

1. **方括号问题**：键值里面绝对不能出现方括号 [ ]。比如你不能写 [#武器=[传说]长剑#]，这样会把整个状态栏搞崩。如果要写特殊物品，把方括号换成其他符号，比如 [#武器=『传说』长剑#]。

2. **GC_UI单独一行**：<GC_UI> 这一行前后不能有任何其他文字。不能在它前面写“好的”，也不能在它后面写空行。

3. **数据行紧贴**：所有 [#xxx=xxx#] 之间不能有空行。你看范例里的数据行都是一行紧挨着一行。

4. **变化字段可省略**：如果这轮某个值没有变化，对应的“变化”字段可以不写。比如你这轮没受伤，就不用写 [#生命值变化=...#] 这一行。

5. **选项的竖杠**：竖杠 | 前面是显示在按钮上的文字（尽量短，10个字以内），后面是点击按钮后追加到输入框的内容（可以长一些）。

6. **数字不带百分号**：写数值的时候只写数字，不要带百分号。正确：`[#生命值=85#]`，错误：`[#生命值=85%#]`。

7. **引擎只认格式**：不管你写什么字段名，只要格式是 [#xxx=xxx#] 就行。你可以自由增减字段，比如加一个 [#魔法值=50#] 或者 [#好感度=80#]，引擎都能识别。

1. 把“二、你必须输出的字段”那个表格里的行，换成你自己的字段。比如你需要追踪“魔法值”，就加一行 | 魔法值 | [#魔法值=50#] | 纯数字，0-100 |。
2. 把“三、完整范例”里的数据换成你自己的世界观数据。
3. 范例里的正文内容和 <GC_UI> 后面的数据行都要替换。
4. 如果你的卡有NPC，就加上NPC字段，格式和玩家字段一样，只是字段名前面加 NPC1、NPC2 这样的前缀。比如 [#NPC1姓名=小李#]、[#NPC1生命值=70#]。

五、常见错误

错误 怎么修
AI在 <GC_UI> 前面写了“好的”之类的文字 在规则里强调“严禁在 <GC_UI> 前后添加任何文字”
数据行之间有空行 在规则里强调“数据行之间不能有空行”
键值里出现了方括号 改成其他符号，比如『』或者【】
某个字段没显示 检查引擎代码里 buildPerson 或 renderUI 是否读取了那个字段名
百分比带了百分号 去掉百分号，只写数字

第一句话状态栏教程

一、什么是第一句话状态栏

第一句话状态栏就是角色卡的开场数据。玩家进卡后，AI还没说话，但你已经把初始数据写好了——轮次是0或1，生命值是满的，位置是初始地点，选项是“开始冒险”之类。

它和后续轮次的状态栏格式完全一样，只是数据是你提前写死的，不是AI生成的。

---

二、它放在哪里

放在角色卡的第一句话里。也就是创建角色卡时，“首条消息”或“开场白”那个框里。

第一句话包含两部分：

1. 正文：正常的开场剧情文字
2. 状态栏数据：以 <GC_UI> 开头，后面跟 [#xxx=xxx#] 格式的初始数据

---

五、常见问题

问题 原因 解决方案
第一句话状态栏不显示 引擎初始化时数据还没就绪 在引擎的 extractData 里加兜底逻辑，直接从气泡原文解析数据
只有后续轮次有状态栏，第一句话是空白 同上 同上
第一句话数据残留，页面上出现了 [#xxx=xxx#] 纯文字 正则1没匹配到，或者数据行之间有空行 检查第一句话里的数据行是否紧贴，不要有空行

六、引擎兜底修复

如果你用的是标准的 Web Components 引擎，在 extractData 方法里加上这段兜底逻辑。它能确保即使第一句话时隐藏的 <span> 还没生成，引擎也能直接从气泡原文里解析出数据：

在引擎代码里找到 extractData 方法，把下面这段加到 return kv 之前：

```js
// 兜底：如果隐藏span里没数据，直接从气泡原文解析（用于第一句话）
if (Object.keys(kv).length === 0 && container) {
  const rawText = container.textContent || '';
  re.lastIndex = 0;
  let m;
  while ((m = re.exec(rawText)) !== null) {
    kv[m[1].trim()] = m[2].trim();
  }
}
```

加完后的完整 extractData 长这样：

```js
extractData(){
  const kv = {};
  const re = /\[#([^=\[\]#]+)=([^\[\]#]+)#\]\s*/g;
  const container = this.closest('.item,.content,uni-view.content') || this.parentElement;
  if (container) {
    container.querySelectorAll('.z-live-data').forEach(n => {
      re.lastIndex = 0;
      const m = re.exec(n.textContent);
      if (m) kv[m[1].trim()] = m[2].trim();
    });
  }
  // 兜底
  if (Object.keys(kv).length === 0 && container) {
    const rawText = container.textContent || '';
    re.lastIndex = 0;
    let m;
    while ((m = re.exec(rawText)) !== null) {
      kv[m[1].trim()] = m[2].trim();
    }
  }
  return kv;
}
```

加完后，第一句话的状态栏就能正常显示了。
