# 同层全屏卡制作规范（新页沙盒实战流派）

来源：作者本机资料《同层全屏卡·制作指南（上/下）》与《魅魔新版·同层卡实战踩坑手册》（均为实机踩坑总结，可直接照抄；原始 extracted 文档未随仓库发布）；官方作者区框架见 WEB_AI_AUTHORING.md（同未发布，可按需联系作者索取）。

## 一、什么是同层卡

只有一个 `position:fixed; inset:0` 的全屏大盒子，开屏/须知/序章/捏人/状态页/正文全住里面，靠 class 切换显示；层外只留左上角"眼睛"开关等一两个小控件。与"塞进聊天气泡"的老做法完全不同：气泡版跟消息滚、宽度受限、被平台样式折腾；同层版铺满全屏固定不动，像独立 App。

数据来源：AI 每轮正文末尾输出文本块（`[状态]…[/状态]`、`【玩家档案】…`），层内脚本解析渲染。

## 二、六个平台硬机制（踩坑手册实测）

1. **statusbar = 接线板**：每个组件规则都要在 statusbar 里有标记，缺一个标记该条规则永远不被注入，样式脚本一起消失。
2. **单条替换上限 2 万字符**：实测 22508 字被平台直接提示"超了2508"，超长必须拆多条规则。
3. **HTML 白名单**：section/aside/header 会被"脱壳"——标签拆掉、class/id 全丢。只用 div/span。
4. **脚本执行时序不保证**：必须轮询启动，不能"加载即绑定"。
5. **sdk.save 按对话隔离**：跨对话数据只读一次会串台，必须定时核对（1.5 秒）。
6. **平台会重建节点**：组件必须自带巡检+重挂，不要长期缓存元素引用，"用的时候再查"。

## 三、组装方式

1. 全部代码通过正则替换注入，一条规则只干一件事；statusbar 按顺序摆标记【1】【2】…，每条规则查找=同名标记、替换=对应代码块。平台机制：style/script 被抽出直接生效，HTML 留原地。
2. 结构块固定套路：`<div class="前缀-view 前缀-src" id="src-前缀-xxx">`，启动脚本把所有 src 块搬进层里（id 去 src- 前缀=目标屏），就位后删原位复制品。
3. 类名统一前缀；全局只用一个 `window.__XXX` 对象共享状态。
4. 进卡自动开层；玩家手动关过（点眼睛）后不再自动弹。

## 四、核心写法八条

1. 防重复安装：`if(window.__XXX) return; window.__XXX = true;`
2. 一切"找元素"轮询：`boot()` 找不到就 `setTimeout(boot,500)`，另挂 `setInterval(boot,1500)` 巡检。
3. 事件一律 document 捕获委托（`addEventListener(...,true)`），不给具体元素绑 onclick（节点会被重渲染）。
4. 层搬家到 body 底部；重渲染时顺手清多余复制品。
5. **层默认 display:none + 打开类才显示。永远不要"默认可见靠 JS 藏"**——JS 一失手全屏层挡死一切操作。
6. 不用自写 data-*；不用 `$` 当变量名（替换语法占用）；只用 div/span。
7. 读消息：不要用 DOM 选择器（`[data-chat="message"]`、`.chat .item` 在这平台匹配不到）。用 `document.body.innerText` 整页快照兜底；多开对话时先把自层 pointer-events 设 none，用 elementFromPoint 探当前滚动容器只读它；可给 body.innerText 打 getter 补丁让全体脚本只读当前对话（空时返回空格防止回退 textContent）。
8. 发消息两级兜底：① sdk.input.set + sdk.message.send()；② 原生 textarea 赋值+触发 input 事件+点发送键。都失败要明确提示玩家，绝不静默。

## 五、拆分与共享（2 万装不下时）

每条规则独立完整，用全局共享口袋传函数和状态：规则A 写 `window.__SHARE={count:0}; __SHARE.fnA=...`；规则B 轮询等 `__SHARE.fnA` 存在再挂自己的函数。

## 六、高频 BUG 速查（症状→修法）

| 症状 | 修法 |
|---|---|
| 全屏点不动 | 全屏层必须 display:none+打开类 |
| 进卡不显示，刷新才正常 | 轮询等待+document 委托 |
| 面板突然消失/点了没反应 | setInterval 巡检重挂，不缓存引用 |
| 状态块读不到 | body.innerText 整页快照兜底 |
| 多开对话串数据 | 会话守卫：elementFromPoint 只读当前容器 |
| 切对话不清零 | 按对话指纹（档案哈希）清零；指纹读不到时静默保持，别硬切 |
| 聊天区出现白字代码 | 裸 CSS 没包 style |
| 定位飞顶/两屏同显 | 用了 section/aside/header，全换 div/span |
| 回溯后显示旧内容 | 整页快照，连续 4 次读不到就清屏 |
| 钱包串台 | 1.5 秒定时核对存档 |
| 输入框挂签一起没 | 脚本语法错，查最近改动的正则 |
| 音乐乱播 | 触发锚"场次+人物+未收场"+按对话存 localStorage+手动闸门三态 |
| 底部行动条挡内容 | 选项单行平铺 flex 等分+省略号；滚动区留 150px 底空白 |
| 文字块被啃/排版乱 | 不自写 data-*、不留 4 空格缩进（变代码块）、避保留字 |

## 七、排错顺序

1. 先分清"没装上"还是"装上了没跑"（控制台报错？层搬到 body 没？）
2. 再查"读"：页面里手动搜 [状态] 字样——在=解析问题，不在=读取范围问题
3. 再查"渲染"：解析值对不对，对=缓存没更新
4. 最后查"自动逻辑"：自动落点/开层/音乐全是锦上添花，可临时降级成手动按钮
5. **一次只改一处、只测一条链路**

## 八、开发顺序

0. 先定数据协议（AI 每轮输出的字段表写进人设），协议不定死后面全乱
1. 层外壳（层+眼睛+屏幕切换+自动开层默认收起）
2. 捏人面板 → 档案自动发送
3. 状态解析+第一个数据页（先跑通"读文本→解析→渲染"链路）
4. 其余页面照抄套路
5. 行动坞（选项单行+输入框+发送）
6. 会话守卫放最后
7. 杂项（音乐闸门等）
8. 开场白（含初始状态块）+全流程自测

## 九、交付自测清单

进卡自动开层 / 眼睛开关且手动关后不自动弹 / 新对话开屏→须知→序章→捏人，回老对话自动落正文 / 捏人确认档案发出 / 发测试状态块 5 秒内刷新 / 选项点击直发防连点 / 回车发送 / 音乐闸门三态 / 手机键盘顶起+不遮挡 / **通读确认没有"默认可见的全屏层"**。

## 十、官方作者区框架（另一套范式，WEB_AI_AUTHORING.md）

平台官方框架提供"作者配置"条目：全局美化（--card-* 主题变量区）、发送处理 beforeSend(draft)、回复状态栏 render(root,{content,message})、舞台 render(root)、流式 stream、完成 render。要点：

- 只填作者区注释之间的内容，保留外壳；每次交付给该位置的**完整最终代码**，不给补丁/增量
- 主题用 `[data-chat="root"]`+主题属性，禁用 html/body/:root/星号选择器
- 状态栏逐回复冻结，不跨轮累计；root 只属于当前回复
- sdk.message.send 必须在玩家点击当帧直接调，调用前不能 await
- 动态正文用 textContent/createElement 写入，不直接赋 innerHTML
- HTML 白名单：p b a div span h1-h6 ul li ol strong em br img pre font i button table input textarea label select option video summary details code blockquote hr del + SVG 子集
- 功能栏（statusbar）≤200 字；规则≤130 条；名称≤20；表达式≤1000；替换内容<20000
