S红线3：别把「消息生成中」当回复
  用户点发送 → 平台立刻挂空AI气泡 → message:mount 马上来，
  此时 msg.content 为空、[data-chat="message-body"] 是占位文案
  ✓ 跟字用 message:stream 的 msg.content（已攒原文）
  ✓ 收尾用 message:done 的 msg.content
  ✗ 禁止在 mount 里读 message-body 当回复；
    content 空时也不要退回去读 DOM（会丢后续 stream/done）
  ✓【v2.4新】判别生成中更稳的做法：生成中的 message-body 带
    data-generating="1"，收尾后去掉——比对比占位文本可靠
    （占位文案平台随时可能改），与 isReplyText 双保险

S红线4：匹配式形态 + 输出预算 + 空串禁令
  ✓ /pattern/flags → 正则（g 平台自动补，不用自己加；flags 仅 gimsuy）
  ✓ 其余任何非空串 → 字面量（元字符被转义，a.b 不会匹配 axb）
  ✓【v2.4推翻】裸字面量实机生效（2026-08-30 卡64304 A/B 对照复验）——
    交付仍统一写 slash /…/（跨平台一致的约定，非硬红线；
    校验器对裸字面量出 WARN 不出 ERROR）
  ✗ /…/ 语法错 → 整条规则被跳过，页面无异常只有告警
  ✗ 字面量匹配式不要重复：规则按顺序跑，前一条换完全文，
    后一条同串永远匹配不到
  ✓【v2.4新】临时停用一条规则：scriptName 加 __ 前缀 → 整条被丢弃
  🚨【v2.4新·输出预算，官方三份资料都没提】每条规则预算 =
    max(262144, 输入长度×4)，按该条规则所有匹配的输出累计；
    超限 → 整条规则静默回滚（页面完全不生效，只在调试面板留一行）
    三种告警：replacement-alone（替换文本本身超）/ volume（匹配次数×
    单次输出累计超——典型是匹配式太松一条消息命中几十处）/ empty-match
  🚨 匹配式绝不能匹配空串：/a*/、/(\d*)/、/[abc]?/ 这类整体可零长度的
    写法会在每个字符位置插一次，瞬间炸预算 → 量词用 + 不用 *，
    可选组别放最外层。注意 /(?!)/ 是恒失败（安全写法），不算空串匹配
  症状识别：「短消息正常、长消息莫名不生效」= volume；
    「整条从来没生效过、页面无异常」= replacement-alone 或 empty-match

S红线5：自己写的 data-* 会被净化删掉
